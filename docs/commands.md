# Command reference

Every script and test aid with its flags. CLAUDE.md keeps only the everyday commands; look here for the rest.

```bat
m1.cmd [-GameDir <dir>]              :: all automatable M1 checks -> %LOCALAPPDATA%\sm-reimpl\discovery\<ts>\m1-report.md
discover.cmd [-GameDir <dir>]        :: read-only inventory -> %LOCALAPPDATA%\sm-reimpl\discovery\
smtool.cmd verify-all <game-dir>     :: parse and decompress every .oppc with checks
smtool.cmd list|verify|extract ...   :: see README; extract takes a path or #index (paths can repeat)
smtool.cmd audio-list|audio-event|audio-decode|audio-verify|audio-mix|audio-levels|audio-tags|audio-surfaces|audio-rtpcs|audio-node|audio-objects ... :: Wwise packages (audio-mix prints each voice's resolved mix for an event, audio-levels ranks the MP events by loudness; footsteps fix); decode writes .ogg/.wav to %LOCALAPPDATA%\sm-reimpl\cache\audio (downloads ww2ogg's codebooks on first use, hash-checked)
client.cmd ... [--log-input] [--pad-test [--pad-test-done]] :: controller (gamepad feature; CONTROLLER section below): `--log-input` prints the scheme changes (keyboard and mouse / controller); `--pad-test` (a human client, no physical controller needed; Godot `--headless` before `--`) injects synthetic joypad events (`Input.ParseInputEvent`) and prints `PADTEST` lines: the scheme switch, look, move, half-stick move, aim, fire, melee, charge, stun, jump, weapon swap, the mouse taking the scheme back, the corrections against the server; `--pad-test-done` quits after. Run it against `server.cmd --bind 127.0.0.1 --port <p>`; with `--class tactical|assault` for the charge and the jump pack
smtool.cmd refine-register [--check] [--list-untagged] :: regenerate docs/refine-register.md (the human-playtest checklist of every estimate, guess or "ours" value, stable R-/C- ids); RUN IT after every spec/behavior.md or changes-from-original.md edit and after every merge that touches them: `dotnet test` fails while the register is stale or a spec row lacks kind/source/confidence
smtool.cmd perks <game-dir|auto>     :: every perk with classes, upgrade string and status (Active / Partial / Inert "NOT ACTIVE YET"), each perk variant and the fields it changes, the player-blueprint upgrades (M43)
smtool.cmd ork-sounds <game-dir|auto> [--clips] [--all-tags] :: the Ork Boy's sounds and barks (O8): each sound/speech command of his blueprint and wargear resolved against the banks, and his clips' behaviour tags
smtool.cmd melee-hit-sounds [--game <dir>] [--out <dir>] [--render] [--count k] :: what the data plays on every multiplayer melee hit (per weapon and ability: hit effect containers, sfx events, voices for armour and flesh, the sim hit time) to table.txt; --render also writes WAV previews and index.html (default folder: the private cache, previewsmelee-hits)
smtool.cmd musou-guard-route [--point k] [--seconds s] [--out dir] :: test aid (musou/guard-spread): the field's six Guard squads walk from Ashfall's landing zone to each position (or k) on the generated map's graph, no Orks, once with GuardRules.Spread and once with the old walk; top-down SVG + PNG per run and route-log.txt (men beside a wall, nearest man on the way, lanes, last man in, fire teams); default folder %LOCALAPPDATA%\sm-reimpl\cache\previews\musou-guard-spread

smtool.cmd ashfall-kit-bake-scales [--layout city|field|draft10] [--out scales.json] :: kit-hi-res (owner 2026-11-09, "all the 3d assets used in the main play map are high res"): each kit model the map places inside the battle arena, the scale of its largest item there along the file's glTF X, Y, Z, keyed by file stem; tools/blender/ashfall_bake.py takes it as --scales and bakes at that size (tools/blender/README.md)
godot.cmd --windowed -- --ashfall-kit-gallery --ashfall-closeup [arena|AC-001,..] [--out dir] [--ashfall-kit-detail old] :: test aid (kit-hi-res): each kit model the city places inside the arena, alone at the size of its largest arena item, in the map's light with its 4 px LOD threshold and the arena's detail rules: ID_near (eye height, 5 to 14 m from its face) and ID_mid (35 m out); `--ashfall-kit-detail old` (also in game) draws every model at 1024 px with the plain LOD threshold, as before the pass; KITPERF lines of `--ashfall-perf` now also give video and texture memory and the renderer
smtool.cmd musou-guard-vantage [--secure k|none] [--seconds s] [--out dir] :: test aid (musou/guard-vantage): the Guardsmen's vantage points on Ashfall's generated map and a battle on its graph with position k secured (default 1; none: the base's front) whose vantage teams leave every 5 to 8 s (the game: 20 to 45 s), frozen Orks; overview.png (whole map, spots, 50 m rings, team trails), closeup.png and vantage-log.txt; default folder %LOCALAPPDATA%\sm-reimpl\cache\previews\musou-guard-vantage
smtool.cmd ranged-hit-confirms [--game <dir>] [--out <dir>] [--count k] :: the shooter hit-confirm event of every MP gun (table.txt) and WAV previews of the data (planned) and the default soft confirm (now) for armour, flesh and kills
smtool.cmd listen-page [--game <dir>] [--out <dir>] [--count k] :: the curated previewsisten.html: per weapon NOW (our build) and PLANNED (the data) players, melee and ranged
smtool.cmd audio-render <event> [--out <dir>] [--seed n] [--count k] [--material armour|flesh] [--local] [--mono] :: offline WAV of k posts of one event (volume, pitch, delay as resolved; no 3D attenuation, no bus effects)

Client: `--no-musou-ork-sounds`, `--musou-ork-gain <dB>` (a listening aid), `--log-sound musou` (a MUSOU SOUND line per post); every 10 s a `musou sounds:` line gives the voices, steals, cost and each group's posts and holds. For a run with no sound from the speakers: `godot.cmd --windowed --audio-driver Dummy -- ...`
smtool.cmd ork-blood <game-dir|auto> :: Musou Mode's original blood (gore-original): the Ork blueprint's dismemberment table (per type and zone: chance and point), each point's effects (scale, marker, direction) and each MP weapon's dismemberment types (shot, every melee ability). Client (Musou Mode): `--old-musou-gore` (the dark trailer gore instead), `--no-musou-gore` (none), `--ork-blood-scale f` (the owner's 1.5x; 1 = the data's size and amount), `--old-blood-colours` (the blood's data colours drawn raw, lighter, as every other effect), `--log-ork-blood` (an ORK BLOOD line per kill: type, zone, point; a count every 5 s); capture aids with `--musou-gore-demo`: `--ork-blood-weapon <wargear>` (every kill and hit by it), `--ork-blood-ability <ability>` (a melee kill's strike, e.g. ability_melee_x3, ability_bullrush_01), `--ork-blood-zone head|body|left_arm|right_arm|left_leg|right_leg` (the point of that zone, its chance ignored), `--musou-gore-case shotkill|headkill|shothits` (one shot kill, head-shot kill, or shot hits on the front Ork)

client.cmd --connect <h:p> --observe [--observe-pose x,y,z,yaw,pitch] [--observe-follow] [--no-hud] :: protocol 46 (ours, footage tool): join as a spectator with a free-fly camera, no player, side, score or body (the lobby menu's SPECTATE button does the same; it is not remembered). Keys: WASD fly along the view, Space/E up, Ctrl/Q down, Shift fast (x4), Alt slow (x0.2), wheel changes the speed (the distance while following), [ and ] the field of view (Backspace resets), G cinematic smoothing on/off, F follows the next living player (Shift+F the previous, past the last back to free-fly; left/right click do the same while following; the mouse then turns the view around the player), H hides the whole HUD (2D, scoreboard, name tags and rings) for clean footage, Tab the scoreboard, F10 back to the menu, Esc frees the mouse. --observe-pose starts the free camera at a game-space place (metres, degrees; yaw 0 faces +Y) instead of the overview; --observe-follow follows the first living player from the start; --no-hud starts with the HUD off. For clean footage also pass --no-markers. A spectator needs a server of the same protocol and content profile; windowed capture runs as every test window (`godot.cmd --windowed -- ...`)
```
