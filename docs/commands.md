# Command reference

Every script and test aid with its flags. CLAUDE.md keeps only the everyday commands; look here for the rest.

```bat
m1.cmd [-GameDir <dir>]              :: all automatable M1 checks -> %LOCALAPPDATA%\sm-reimpl\discovery\<ts>\m1-report.md
discover.cmd [-GameDir <dir>]        :: read-only inventory -> %LOCALAPPDATA%\sm-reimpl\discovery\
smtool.cmd verify-all <game-dir>     :: parse and decompress every .oppc with checks
smtool.cmd list|verify|extract ...   :: see README; extract takes a path or #index (paths can repeat)
smtool.cmd audio-list|audio-event|audio-decode|audio-verify|audio-mix|audio-levels|audio-tags|audio-surfaces|audio-rtpcs|audio-node|audio-objects ... :: Wwise packages (audio-mix prints each voice's resolved mix for an event, audio-levels ranks the MP events by loudness; footsteps fix); decode writes .ogg/.wav to %LOCALAPPDATA%\sm-reimpl\cache\audio (downloads ww2ogg's codebooks on first use, hash-checked)
smtool.cmd refine-register [--check] [--list-untagged] :: regenerate docs/refine-register.md (the human-playtest checklist of every estimate, guess or "ours" value, stable R-/C- ids); RUN IT after every spec/behavior.md or changes-from-original.md edit and after every merge that touches them: `dotnet test` fails while the register is stale or a spec row lacks kind/source/confidence
smtool.cmd perks <game-dir|auto>     :: every perk with classes, upgrade string and status (Active / Partial / Inert "NOT ACTIVE YET"), each perk variant and the fields it changes, the player-blueprint upgrades (M43)
smtool.cmd ork-sounds <game-dir|auto> [--clips] [--all-tags] :: the Ork Boy's sounds and barks (O8): each sound/speech command of his blueprint and wargear resolved against the banks, and his clips' behaviour tags
smtool.cmd race-parity <game-dir|auto> [--raw] [--fx-colours [word]] :: Chaos wargear vs loyalist twin: pairs in the install, simulated-spec differences before/after parity (after must be 0), class defaults, config hashes; --raw lists the files' differing values; --fx-colours the hue of each effect a plasma (or other) weapon plays (weapons task A)
smtool.cmd gfx-dump <game-dir|auto> [--movie Hud|HudText|HudEventLog|Decorator] [--package common] [--grep w] [--frames sprite] [--path a/b --frame n [--top-frame]] [--render name [--all-frames]] [--out dir] :: the HUD movies' sprites, labels, placements and text fields; renders into the private cache's gfx-dump folder by default (never inside the repository or the install; ui/hud-fidelity)
client.cmd --connect <h:p> [--camera-lag ms] [--old-hud] [--hud-movies-fail] :: ui/hud-fidelity: the camera lag (temporary, default 50, 0 off), the M44 HUD, the movies' read made to fail (fallback test aid)
smtool.cmd weapon-dps <game-dir|auto> [--data] [--range m] [--all] :: body-shot DPS (perk variants included) of the bolters and bolt pistols (burst, sustained; health scale and against a full marine) and the owner's overrides before/after (OwnerBalance)
smtool.cmd fx-dump <game-dir|auto> <name|word>... [--list] [--fields] :: the element tree of each named effect of master_fx (--list: effect names containing each word); --map <map> [--where]: the map's looping effects, their god-ray beams and places (fx/impact-pass)
smtool.cmd weapon-parts <wargear> [--markers] [--profile <locator,locator>] [--exhaust <word>] :: weapon models: parts, locators, surfaces and materials (--markers); --profile the model's width along an axis between two locators (the power sword's blade band); --exhaust where the model ends along matching locators' +Y (jump-pack nozzle exits)
client.cmd                           :: Godot client, no arguments: the front end (Join screen: server, side, loadout strip, CUSTOMIZE, JOIN; downloads Godot on first use); --menu / --customizer / --appearance open a screen directly, --profile <json> (profile outside the repo), --loadout <default:role|1..10>, --lock-demo
client.cmd (front end, first run) :: finds the install by itself (explicit path, SM_GAME_DIR, config/local.json, `<data>/settings.json` "gameDir", discovery, Steam registry + libraryfolders.vdf + appmanifest_55150) and shows the game-folder screen (Browse, Retry) when it cannot; Join screen shows where it was found; "Host a match" appears when SmServer(.exe) sits next to the client or in server/ (`--server-exe <path>` overrides; test aids --auto-host --host-port N --host-mode annihilation|seize --host-lan --host-emblems --host-bots 0..15|none|4v4|8v8 --host-difficulty easy|normal --host-stop-others; fix/connect-timeout: hosting starts no bots unless BOTS (0..15, applied at the start) says so, each bot logs to logs\bots\ (STOP SERVER; spec "Connect timeout, hosting checks and hosted bots"), a join with no answer gives up after 10 s; --setup-path <dir>); SM_STEAM_DIR replaces the Steam lookup (tests; empty = none)
client.cmd --viewer [--anim <a>] [--bones] :: the old default view: animated MP Space Marine (any of --anim --time --bones --chaos --stance --weapons --worn --hand --view --paint --focus also keep it; the bare screenshot call needs --viewer)
client.cmd --archive <p> --mesh <n>  :: one static model instead (e.g. an MP map statue)
server.cmd [--port 27015] [--map m] [--mode annihilation|seize] [--countdown s] :: headless dedicated server (UDP); map default mp_tdm_09 (Manufactorum), "none" = flat; --countdown = seconds of "MATCH BEGINS" before play (default 5, 0 none, at most 600; ours); --ork-data = the Ork Boy with the data's values instead of the Tactical parity (test aid, Ork O5; clients need --ork-data too, else ConfigMismatch)
                                     ::  --content faithful|extended|orks,gore = the added content (default extended; faithful = SM1 alone, no Ork; printed at startup; clients need the same --content, else ConfigMismatch naming the server's profile; a -p:SmExtras=false build runs faithful only)
                                     ::  --bind 127.0.0.1 = this machine only (test runs: no firewall prompt)
                                     ::  --honor-side-requests = a requested side is kept up to 8 per side, no balancing (test aid, ours; bot fills in uneven teams; default off)
                                     ::  --max-per-ip N (4; 0 off) --join-interval s (5; 0 off) --idle-kick s (300; 0 off) --ban-file <path> (IP/CIDR per line, re-read on change); --help;
                                     ::  loopback (local bots) exempt from those three unless --limit-loopback; exit 1 no game / bad map, 2 bad flags, 3 port in use, 4 ticks failing 2 s (restart it; docs/dedicated-server.md)
                                     ::  --pickup-test <s> = test aid: one drop of each type in front of every living player every s seconds
                                     ::  --bot-damage-scale f = test aid: every hit a test bot (client --bot, marked in its Hello) deals x f, 0..1 (default 1 = off; only lowers; owner's playtest: 0.34)
client.cmd --connect <host:port>    :: networked client (--show-markers shows the zone indicators hidden since M36: Seize Ground point columns, ground-pound and landing rings, spawn-room shield planes; --no-markers hides every test overlay): WASD, Shift sprint, mouse/Left-Right arrow look (Q/E until fidelity gap 1), E pick up a dropped box (--bot-pickups: bots collect; --no-pickups), LMB fire (charge weapons: tap = normal shot, hold = charged shot; owner's decision), Left Ctrl (hold) aim mode, R reload (detonates launcher grenades), RMB/V melee (in the air: ground pound), F stun strike (heavy melee; with W held: the charge, A or D with it 25 degrees to that side, protocol 39; user's knowledge), G grenade, Space evade (Tactical roll, Devastator hop; jump pack classes: jump), X switch, F1 info overlay, --no-sound (--class tactical|assault|devastator|raptor|havoc|ork (Ork O5: the Ork Boy, drawn as an Ork since O7a: model, weapons, walk, run, aim and sprint; no reactions, melee, hop, reload or death clips yet; `--no-ork-model` draws the old placeholder marine), --primary/--pistol/--melee/--equipment <name>, --side marines|chaos, --ork-data (must match the server's), --content <profile> (must match the server's; default extended), Tab scoreboard, --bot)
bots.cmd --connect 127.0.0.1:<port> --marines N --chaos M [--classes ..] [--accuracy 0..1] [--range m] :: M44a test aid: starts up to 6 headless `--bot --no-sound` Godot clients per side on a test server (start it with `--bind 127.0.0.1 --honor-side-requests`); `bots.cmd --stop` / `--status` act only on the bots it started (PIDs and start times in %LOCALAPPDATA%\sm-reimpl\tmp-build\bots\bots.pids; the Godot process tree is stopped); refuses the live ports 27015/27016/27020/27025, non-loopback hosts without `--allow-remote`, and log/trace folders inside the repo or the install. Bot aids on `client.cmd --connect --bot`: `--bot-accuracy` (default 0.03 plus a trigger discipline since weapons/spread: bots miss most shots; 1 = perfect aim and no discipline, which probe flags such as --aim-test imply; `--bot-no-discipline`), `--bot-range`, `--bot-no-spawn-wait`, `--bot-trace <file>`
movie.cmd --movie-size WxH --write-movie f.avi [--fixed-fps 30] <client args> :: Movie Maker recording at a chosen size (M34; per-run copy of the client project with that viewport size under %LOCALAPPDATA%\sm-reimpl\cache\movie-project; project.godot untouched)
client.cmd ... --no-stomp-fx | --no-sword-fx | --old-pack-trail | --god-rays | --look current :: fx/impact-pass before / after aids: no stomp or slam impacts, no power sword glow or flare, the old long thrust trails (and flame and placement), the map's god rays, the previous default lighting look; --stomp-ring <sprite> (the shockwave's ring sprite), --log-melee-fx (prints each stomp and sword hit shown)
client.cmd --stomp-test [--fx <name>] [--pound-radius m] [--stomp-ring <sprite>] [--no-shards] :: effects test view: a stomp's impact as the networked client plays it (fx/impact-pass; default interrupt_stomp_dmg at radius 7)
                                     ::  --position -4000,-4000 starts the recording window off-screen (with --test-window)
client.cmd --lighting off|low|medium|high :: M42 lighting preset (default medium; high opt-in: PCSS, SSR, full-res SSAO/SSIL); --fx-hard draws effect cards without the M42 fades; --look-set k=v,... tunes single constants (vf.haze = smog thickness); --look sm1|remaster|moody|forge = the lighting mockups for the owner's choice (client/LookPresets.cs; default look unchanged)
client.cmd --connect <h:p> --record-demo <file> [--record-seconds s] :: record a real-time session (M40-T0; relative names under %LOCALAPPDATA%\sm-reimpl; never inside the repo or the install; demos hold other players' looks and emblems: keep them private)
movie.cmd ... --play-demo <file> [--demo-no-quit] :: replay a demo on Godot time (no server): time-faithful Movie Maker footage; --motion-probe [--motion-probe-worst], --old-render-clock (before/after test aids)
client.cmd ... --camera-probe [--camera-selftest] [--spectate-cuts] :: M40-T6 camera aids: log near-plane-in-collision and jump frames (raw and 60 fps-normalised); synthetic body-push cases; spectator views snap instead of blending (--spectate cam:x,y,z,tx,ty,tz is placed exactly)
release.cmd [-AllowDirty] [-Smoke] [-Linux] [-Commit <rev>] :: builds the tester release into %LOCALAPPDATA%\sm-reimpl\release\<version>\: ONE playtest zip for testers (SM-Reimpl-Playtest-<date>-<ver>-Windows.zip: numbered "1 - READ ME FIRST.txt", "2 - Play.cmd", "3 - Host a match on this PC.cmd", "4 - Join a server by address.cmd", "5 - Host a match for friends (LAN).cmd" at the top; game\ server\ source\ notes\), plus the win64 server zip and the source zip for server hosts (the linux-x64 server package only with -Linux or -ServerAssets), SHA256SUMS.txt and RELEASE-NOTES.md (the tester-facing description: steps, keys, the zip's SHA-256); content guard (`smtool scan-package`, nested zips too; the install's and the cache's file fingerprints kept in %LOCALAPPDATA%\sm-reimpl\cache\guard, never in the install); every run ends with each step's seconds and the total; -Smoke runs the zip's launchers headless on 127.0.0.1; -Commit re-packages an older commit's programs; publishes nothing unless the owner passes -Publish (gh draft pre-release in Yeezima/sm-reimpl-releases with the playtest zip only; -ServerAssets adds the servers and source; -DryRun prints the command). README "Building a tester release"
ship.cmd [-DryRun] [-Draft] [-ArchiveOnly] [-Supersede] [-KeepPrevious] [-Playtest] [-SkipTests] [-NotPrerelease] [-NoPush] [-Linux] :: OWNER ONLY, the one-command playtest release (release.ps1 -Ship): preflight (clean main = origin/main, dotnet test and refine-register --check unless both passed on this exact commit within 24 h (test-and-mark.cmd's marker; the ship says it skipped them), release/NEXT.md tester-facing, version not yet released), build, guard, smoke, gh release create (published pre-release; -Draft), What's new from release/NEXT.md at the top of the description, then NEXT.md archived to release/history/<version>.md in one commit on the shipped commit, pushed only while origin/main is still it (-Draft: archive later with -ArchiveOnly); -Playtest restarts the local playtest server 127.0.0.1:27025 with 7 bots; -DryRun prints the checks and every command. Feature PRs add tester-facing bullets to release/NEXT.md (content only). docs/releasing.md
test-and-mark.cmd [-Check]          :: dotnet test + smtool refine-register --check; both green on a clean tree = %LOCALAPPDATA%\sm-reimpl\tmp-build\tested\<sha>, so ship.cmd of that commit within 24 h skips its test run (-Check: only report)
client.cmd ... --frame-profile [--frame-profile-warmup s] [--no-hitch-fixes] :: M40-T9: per-subsystem frame times (p99.9, worst, ms and KB per phase, hitch frames with their phase and GC) every 5 s and at the end, the join (first s seconds, default 8) apart; --no-hitch-fixes = no spreading and no warm-ups in the same build (before / after; not byte-identical to pre-T9: the reused sets, the finer phase marks and the shared animation table stay)
smtool.cmd graph-dump --melee-flow   :: anim/melee-flow: each melee weapon graph's entry, chain and exit blends per strike (also --locomotion now lists the hammer's run and idle)
client.cmd ... --no-melee-flow | --no-clip-foot-lock | --no-stun-shake | --stun-shake-scale f | --log-stun-shake | --charge-turn-snap :: anim/melee-flow before / after aids: every change off; the clip foot lock off; no stun-strike shake (or scaled; logged); the charge's one-frame body snap
client.cmd ... --transition-probe --transition-probe-clips [--clip-lock-trace PlayerN] :: the transition probe with melee and charge clips labelled by name (a combo's step to step is a switch); one line per foot and frame of the clip foot lock on that character
client.cmd --connect <h:p> --bot --bot-turn-rate <deg/s> :: anim/melee-flow test aid: a fighting bot's view turns at most this fast instead of in one tick (recorded fights measure the animation, not the bot's view snaps)
dotnet test                          :: synthetic-fixture parser tests and netcode acceptance tests
faithful-build.cmd [dotnet test args] :: the solution and the client built with -p:SmExtras=false (no Extras/ folder, SM_EXTRAS undefined, only --content faithful runs), then dotnet test of that build: the compile-time gate (a faithful match = server.cmd and client.cmd with --content faithful on the usual build); outputs in the git-ignored .faithful-build/, the Godot client's in .faithful-build/godot (docs/added-content.md)
```
